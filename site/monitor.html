HR Data Quality Monitor

It reads an HR extract, finds records that would break payroll, reporting or approvals, and tells someone how to fix each one.

Designed by Lamin Beyai and built with AI assistance, using Python, SQL, dbt and DuckDB. Back to the portfolio.

Every person, salary and company here is fictional. Errors were planted on purpose.

Can the checks be trusted?

Errors with known locations were planted in the data, along with unusual records that are valid. The monitor had to find the first group and leave the second alone.

This shows the rules do what they were written to do. It doesn't show how they'd perform on a real company's data, which would contain errors nobody has planned for.

How it works

  1. Generate. Python creates a fictional company, then plants known errors.
  2. Model. dbt types the raw extract in DuckDB without losing the original values, then builds reporting tables.
  3. Check. Rules in SQL and Python flag records and explain why each one matters.
  4. Prove. Automated tests compare findings with the planted errors across several random datasets.
  5. Publish. This page and the CSV files are rebuilt from the results.
