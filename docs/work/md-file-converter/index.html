The MD File Converter

Any file in, clean Markdown out, ready for AI. One book went from 359,528 tokens to 285,245.

Tools
Python, FastAPI, pandas, JavaScript, pytest
Talk to me about this

The problem

AI tools count everything you give them in tokens, and they can only hold so many at once. A PDF, a web page or an e-book carries layout, styling and markup the model has no use for. You pay for all of it, again on every message. Some files the model cannot open at all.

What I did

This is my own tool. I made it so that any file can go into an AI conversation as clean Markdown: the words and their structure, nothing else. I set three rules for it: it runs offline, it fits on one screen, and it never refuses a file.

The test corpus is built from awkward files: a scanned PDF, a file with the wrong extension, an empty file, a database.

How it works

A local app: a Python and FastAPI server on the machine, and one page in the browser. Every file goes through the same three stages.

  1. Sniff. The app never trusts the file extension. It reads the first bytes, opens containers and works out what the file really is.
  2. Convert. Each kind of file has an ordered chain of engines. The first one that returns content wins. If all fail, a salvage engine still returns a card describing the file.
  3. Polish. Twelve passes clean the raw output: broken hyphens, wrapped lines, heading levels, tables, lists, links, then a front matter block that says where the text came from.

The result

I measured it on one book, Moby-Dick. As a web page it is 359,528 tokens. As the Markdown this tool made from it, 285,245 tokens. That is 74,283 tokens saved, about 21%, every time the book goes to a model. From the e-book file the saving is about 24%. The same context window now holds more of your material. It is a working desktop app, with 260 tests behind it.
