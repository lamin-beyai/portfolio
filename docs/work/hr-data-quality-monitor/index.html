Public HR data-quality monitor

All 91 planted errors found, with no false alarms on 9 valid edge cases. Everything here runs on a fictional company.

Tools

Talk to me about this

The problem

A monthly HR report is only as good as the file behind it. Too often the errors are found by the people reading the report, after it has gone out.

What I did

Work done for an employer stays with that employer. So I rebuilt the idea from scratch, in public, on a fictional company.

Tests on new random datasets exposed a bug that the first clean run had hidden.

How it works

dbt on DuckDB, the rules in Python, and the same rules running in your browser.

A generator creates the company and plants 91 errors plus 9 records that look wrong but are valid. dbt models on DuckDB shape the raw file, the rules check it in Python, and the same rules run in your browser. Tests prove the two versions agree.
