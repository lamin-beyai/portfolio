Construit en public, données fictives · 2026

Moniteur public de qualité des données RH

Les 91 erreurs plantées sont trouvées, sans fausse alerte sur 9 cas limites valides. Tout tourne sur une entreprise fictive.

Outils
Python, dbt, DuckDB, pytest, JavaScript
En parler

Le problème

Un rapport RH mensuel ne vaut que le fichier qui le nourrit. Trop souvent, les erreurs sont trouvées par ceux qui lisent le rapport, une fois envoyé.

Ce que j'ai fait

Le travail fait pour un employeur reste chez lui. J'ai donc reconstruit l'idée de zéro, en public, sur une entreprise fictive.

Des tests sur de nouveaux jeux de données ont révélé un bug que le premier résultat parfait avait caché.

Comment ça marche

dbt sur DuckDB, les règles en Python, et les mêmes règles dans votre navigateur.

Un générateur crée l'entreprise et plante 91 erreurs ainsi que 9 dossiers qui semblent faux mais sont valides. Des modèles dbt sur DuckDB préparent le fichier brut, les règles le contrôlent en Python, et les mêmes règles tournent dans votre navigateur. Des tests prouvent que les deux versions concordent.

Essayez

Toutes les règles sur toute l'entreprise fictive, avec ses 91 erreurs plantées.

Passer votre propre export aux règles Ouvrir la première édition

Le résultat

Les 91 erreurs trouvées, sans fausse alerte. Données fictives uniquement.
